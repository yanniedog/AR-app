# Local receipt reopening

The calculator's **Open calculation receipt** route accepts an explicitly pasted local record (8 MiB maximum; bounded structure and per-account inputs). Internal digests detect mismatches, not authenticity. Saved summaries remain labelled unverified.

Supported current records are eligibility assessments, savings periods, mortgage periods, independent savings holdings comparisons, historical mortgage comparisons, and private envelopes for single or compared term deposits. The private TD envelope leaves the canonical adapter and engine result unchanged. It retains scoped local answers and the original template as a hash-checked selection proof, never as executable current authority. Older single-deposit receipts are view-only; older deposit comparisons reopen without inferred customer answers.

Every account resolves through the actual adopted-source loader. Users choose a current scope explicitly and confirm changed editions, scopes or rate variants. Execution uses fresh immutable handles and the existing adapters, with an isolated profile overlay. Imported contracts, approval flags and profile definitions are never executed or saved to the customer profile. Copy rechecks current authority by recalculating through the same adapters.

Pasted-text, local-input and source changes invalidate visible results. Unknown answers remain unknown. Missing or revoked current source support prevents recalculation; retaining an old receipt does not retain current approval. This is local input reuse, not bank acceptance, source activation or native-device verification.
